# Claude Code AI社員構築テンプレ v2

このテンプレは、短い「あなたは◯◯担当です」プロンプトではありません。

AGI CAMPで扱うAI社員は、人格設定をしたチャットbotではなく、**ナレッジを読み、ルールに従い、スキルで同じ作業を再現し、成果物を残す実行担当**です。

だから最初に作るべきものは、かっこいいプロンプトではなく、AI社員が迷子にならないための「オフィス」です。

- 何を読むか
- 何を読まないか
- どこへ保存するか
- 何をもって完了とするか
- 失敗した時に何をログとして残すか
- 次回同じ失敗をしないために、どのルールへ追記するか

この6つが決まっていないAI社員は、毎回初出勤のバイトと同じです。
前回の判断も、過去の成果物も、会社の文体も、禁止事項も忘れます。

このテンプレは、Claude Codeを「単発の便利AI」ではなく、会社や個人の仕事を覚えて働くAI社員に近づけるための初期設計書です。

## 0. まず作るフォルダ構造

最初は次の最小構成で十分です。

```text

├── AGENTS.md
├── MEMORY.md
├── USER.md
├── SOUL.md
├── 00-rules/
│   ├── writing-style.md

│   └── README.md
```

重要なのは、最初から巨大なAI組織を作らないことです。
まず1体だけ作ります。
1体が安定して動いたら、役割を分けます。

## 1. AGENTS.md テンプレ

`AGENTS.md` は、そのワークスペースでAIが最初に読む憲法です。
ここに曖昧なことを書くと、すべてのAI社員が曖昧になります。

```markdown
# AGENTS.md

このワークスペースでは、AIは作業前に必ず次を確認する。

1. `SOUL.md` - どういう姿勢で働くか
2. `USER.md` - 誰を助けているか
3. `MEMORY.md` - 長期的に守る方針
4. 今日と昨日の `memory/YYYY-MM-DD.md` - 直近の文脈
5. 作業対象の部署 `_RULE.md`
6. 作業対象の `SKILL.md`

## 基本原則

- 勝手に外部送信しない
- 勝手に公開しない
- 勝手に削除しない
- 作業ログを残す
- 成果物は確認しやすい形式にする
- 迷ったら、目的、入力、出力、完了条件に分解する

## 完了条件

作業完了時は必ず次を報告する。

- 何を作ったか
- どこに保存したか
- 何を確認したか
- まだ人間が見るべきこと
```

## 2. AI社員 `_RULE.md` テンプレ

`_RULE.md` は、そのAI社員の役割境界です。
人間でいう「職務定義書」です。

```markdown
# {AI社員名}

## 役割

このAI社員は、{担当業務}を担当する。
目的は、{目的}を毎回同じ品質で実行できるようにすること。

## やること

- {業務1}
- {業務2}
- {業務3}

## やらないこと

- 外部送信
- 決済、契約、返金判断
- 未確認情報を断定すること
- 他部署の正本を書き換えること

## 最初に読むもの

- `AGENTS.md`
- `MEMORY.md`
- この `_RULE.md`
- `knowledge/`
- 実行する `SKILL.md`

## 出力先

成果物は必ず `output/archive/YYYY-MM-DD_slug/` に保存する。

## 品質基準

- 入力、処理、出力、確認が分かる
- source-mapがある
- 人間が見ればすぐ確認できる
- 次回改善できるログがある
```

## 3. `SKILL.md` テンプレ

`SKILL.md` は、毎回同じ作業を再現する手順書です。
プロンプトを長くするより、手順をファイル化した方がAI社員は育ちます。

```markdown
# {スキル名}

## いつ使うか

ユーザーが「{起動語}」と言った時に使う。

## 入力

- 目的:
- 対象読者:
- 使ってよい素材:
- 触ってはいけないファイル:
- 出力形式:
- 保存先:

## 手順

1. 必読ファイルを読む
2. 目的を1文に要約する
3. 入力素材を一覧化する
4. 作業範囲を確定する
5. 成果物を作る
6. QAする
7. source-mapを書く
8. 完了報告する

## QA

- [ ] 指定された素材だけを使った
- [ ] 保存先が合っている
- [ ] 未確認URLを断定していない
- [ ] 外部公開していない
- [ ] 次回に使える改善メモを残した
```

## 4. Claude Codeへ最初に貼るプロンプト

```text
あなたは、このワークスペースのAI社員構築担当です。

目的:
Claude Codeを単発チャットではなく、ナレッジを読み、ルールに従い、スキルで作業を再現し、成果物を残すAI社員として動かしたいです。

まずやってほしいこと:
1. 現在のフォルダ構造を確認してください。
2. `AGENTS.md`, `MEMORY.md`, `USER.md`, `SOUL.md` があるか確認してください。
3. なければ、最小テンプレ案を作ってください。
4. 最初のAI社員を1体だけ提案してください。
5. そのAI社員に必要な `_RULE.md`, `SKILL.md`, `knowledge/`, `output/archive/` の構成を作ってください。

制約:
- 外部送信、公開、削除はしないでください。
- 既存ファイルを変更する前に、変更対象と理由を説明してください。
- 成果物は確認しやすいパスで示してください。

完了条件:
- 作成したファイル一覧
- それぞれの役割
- 次に人間が確認すべきこと
- 追加で必要なナレッジ
を報告してください。
```

## 5. AI社員に読ませるナレッジの作り方

ナレッジは、長ければ良いわけではありません。
AI社員が判断に使える形になっている必要があります。

良いナレッジ:

- 商品名、価格、対象者、NG表現が分かる
- 以前の成功例と失敗例がある
- どの文体で書くかが分かる
- 何を優先して、何を捨てるかが分かる
- URLや素材の正本が分かる

悪いナレッジ:

- 会話ログをそのまま貼っただけ
- 古い情報と新しい情報が混ざっている
- どれが正本か分からない
- 例外条件が書かれていない
- 完了条件がない

## 8. AI社員の育成ループ

1回作って終わりではありません。
AI社員は、出力に対して人間が戻した修正をルールに残すことで育ちます。

```text
今回の出力で良かった点:
- 

今回の出力で直すべき点:
- 

次回から守るルール:
- 

追記先:
- `{AI社員}/_RULE.md`
- `{AI社員}/knowledge/{topic}.md`
- `{AI社員}/skills/{skill}/SKILL.md`
```

## 9. よくある失敗

- いきなり30人のAI社員を作ろうとする
- 役割だけ作って、読むナレッジがない
- プロンプトだけ長くして、保存先と完了条件がない
- 外部送信や公開のルールが曖昧
- source-mapを残さず、次回なぜそうなったか分からない
- 人間の判断をAIが勝手に確定してしまう

## 10. 最初の1体としておすすめ

初心者は、まず `content-brain（発信脳）` を作るのが一番分かりやすいです。

役割:

- Daily Noteを読む
- 学びを整理する
- X投稿案を作る
- メルマガの種を作る
- Brain記事の導入文を作る
- 次に深掘りすべきテーマを提案する

理由は、成果物が目で見えるからです。
発信が作れるようになると、次にLP、スライド、LINE、セミナー、CSへ広げられます。


## 11. 出力形式別 QA ゲート

AI社員は「作った」と言いがちです。
でも人間が欲しいのは、作ったことではなく、使える状態になっていることです。

| 出力形式 | 確認すること |
|---|---|
| Markdown記事 | 見出し構造、本文量、読者の痛み、具体例、CTA、未確認情報の明記 |
| HTMLページ | スマホ表示、画像表示、リンク、ボタン文言、noindex要否、ページタイトル |
| Excel | 実ファイル生成、シート名、フィルタ、列幅、文字切れ、出典URL、更新日 |
| ZIP | 不要ファイル除外、README、文字化けしにくいファイル名、展開後の入口、サイズ |
| LINE文 | 冒頭の反応、URL直貼り、長すぎない説明、期限、問い合わせ先 |
| スライド | 1枚1メッセージ、文字量、画像比率、PDF化、スクショ確認 |

## 14. Claude CodeとCodexの引き継ぎプロンプト

```text
Claude Codeで設計した内容を、Codexで実装・検証したいです。

Claude Code側で決まっていること:
- 目的:
- 入力:
- 出力:
- 触ってよいファイル:
- 触ってはいけないファイル:
- 完了条件:

Codexにお願いしたいこと:
1. まず関連ファイルを読み、設計と矛盾がないか確認してください。
2. 実装・編集してください。
3. 可能な範囲でテスト/HTML構文/リンク/Excelオープン確認をしてください。
4. 変更ファイル、確認結果、残リスクを報告してください。

禁止:
- 勝手な公開
- 勝手な削除
- 未確認URLの断定
- ユーザーが作った変更の巻き戻し
```

## 15. これを守るだけでAI社員っぽくなる最低ライン

- 読むものを決める
- 読まないものを決める
- 保存先を決める
- 完了条件を決める
- source-mapを残す
- QAをする
- 次回の改善をルールに残す

この7つがあるだけで、単発プロンプトからAI社員に近づきます。

## 17. AI社員を育てるための週次レビュー

```text
今週のAI社員の出力をレビューしてください。

見てほしいもの:
- 今週作った成果物
- 修正が多かった箇所
- 人間が何度も説明したこと
- 失敗した外部URL/ファイル/表現

出してほしいもの:
1. AI社員が覚えるべき新ルール
2. knowledgeに追加すべき情報
3. SKILL.mdに追加すべき手順
4. 次週から減らせる人間の確認
5. まだ人間が判断すべきこと
```
