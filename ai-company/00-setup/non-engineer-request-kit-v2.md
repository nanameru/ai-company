# 非エンジニアAI社員依頼文キット v2

このキットは、非エンジニアがAI社員へ仕事を渡すための依頼文集です。

重要なのは、専門用語を知っていることではありません。
AI社員に対して、**目的、入力、禁止事項、出力、完了条件**を渡せることです。

「いい感じに作って」は、AI社員にとって一番困る依頼です。
逆に、プログラミングができなくても、次の5つを渡せればAI社員はかなり動きやすくなります。

1. 何のために作るか
2. 誰が使うか
3. 何を読んでよいか
4. どこへ保存するか
5. 何を確認したら完成か

## まず覚える基本形

```text
やりたいことは「{目的}」です。
対象は「{対象者}」です。
使ってよい情報は「{素材}」です。
使ってはいけない情報は「{禁止素材}」です。
出力は「{形式}」で、「{保存先}」に置いてください。
完成条件は「{確認できる状態}」です。

まずは完成版ではなく、作業範囲と構成案を出してください。
不明点があれば、作業前に質問してください。
```

## 悪い依頼と良い依頼

悪い依頼:

```text
12大特典いい感じにして。
```

良い依頼:

```text
12大特典のうち、04/06/10/11の中身が短すぎるので強化してください。
04と06は、AI社員構築の考え方、AGENTS.md、MEMORY.md、SKILL.md、QA、source-mapまで踏まえた長文プロンプトにしてください。
10は、GitHub高スターのOSS/ローカルAIを50個ほど選び、Excelで比較できるようにしてください。
11は、非エンジニアがそのままAI社員へ貼れる依頼文キットにしてください。
最後に、受け取りページ、GigaFile ZIP、LINE返信文まで更新してください。
```

違いは、後者には「どこが悪いか」「どう直すか」「どこまでやるか」「何を更新するか」が入っていることです。

## QA依頼の型

```text
次の成果物をQAしてください。

対象:
{URL/ファイル/フォルダ}

確認してほしいこと:
- リンクが開けるか
- スマホで読めるか
- Excel/ZIPが開けるか
- 未確定URLが残っていないか
- 受け取る人が次に何をすればよいか分かるか

QA結果は、重大度順に書いてください。
問題がなければ「問題なし」と書き、残リスクも書いてください。
```

## AI社員への依頼で絶対に入れるべき5項目

| 項目 | 書くこと | 例 |
|---|---|---|
| 目的 | なぜやるか | LINE登録者が12大特典を迷わず受け取れるようにする |
| 入力 | 読んでよいもの | 既存12特典フォルダ、ユーザー指定URL |
| 禁止 | やってはいけないこと | 外部送信、不要ファイル混入、未確認URL断定 |
| 出力 | 欲しい形式 | HTML、Markdown、Excel、ZIP、LINE文 |
| 完了条件 | 確認できる状態 | 本番URL 200、GigaFile 200、LINE自動返信有効 |

## 最後に

非エンジニアがAI社員を使う時に必要なのは、コードを書く力ではありません。
仕事を分解し、AIに渡せる形にする力です。

AI社員は、曖昧な願いを読む魔法ではありません。
ただし、目的、入力、禁止事項、出力、完了条件を渡せば、かなりの仕事を任せられます。

## AI社員に戻すフィードバックの書き方

AIへのフィードバックは、感想ではなくルール化できる形で返します。

悪い例:

```text
なんか違う。もっと良くして。
```

良い例:

```text
今回の問題は3つです。

1. 文字数が短すぎて、受け取った人が実際に使えません。
2. 市岡のAI社員文脈、つまりナレッジ、RULE、SKILL、source-map、QAの考え方が入っていません。
3. URLで渡すものとGigaFileで渡すものが分かれていません。

修正方針:
- 04/06/11は、そのまま貼れる長文プロンプト集にしてください。
- 10はExcel実ファイルにしてください。
- 07は指定Google Docs URLを正本として扱ってください。
- 最後にLINE返信文も直してください。
```

## 迷った時の万能依頼文

```text
私の依頼が曖昧な可能性があります。
いきなり作業せず、まず次の5項目に整理してください。

1. 目的
2. 入力
3. 禁止事項
4. 出力
5. 完了条件

そのうえで、不明点があれば最大5つだけ質問してください。
質問なしで進められる場合は、作業計画を短く出してから進めてください。
```

## AI社員へ「品質優先」と伝える時の言い方

```text
速度より品質を優先してください。
ただし、品質とは長く書くことだけではありません。

品質の定義:
- 受け取った人がそのまま使える
- 保存先が分かる
- URLが開ける
- Excel/ZIP/HTMLなど実ファイルがある
- 確認方法がある
- 次回更新できる
- 不要なファイルが混ざっていない

この基準で作業してください。
```
